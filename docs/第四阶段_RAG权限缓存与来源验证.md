# 第四阶段：RAG 权限、索引缓存与来源验证

更新日期：2026-09-21。对应总修改意见中的第四阶段：RAG 权限统一 → 索引缓存 → 来源可信度完善。

## 已完成与原因

| 原问题 | 本次修改 |
| --- | --- |
| 每次问答重新 fit_transform | 按可见内容范围缓存 TF-IDF vectorizer 和稀疏矩阵，后续问题仅 transform |
| 索引只比较文章 ID，原文和权限改动不更新 | 对已发布内容完整快照计算指纹，正文、权限、来源等任一变化自动重建 |
| 历史答案仅校验用户 ID | 读取来源时重新核验内容版本、用户当前权限及有效期 |
| source_department 固定返回空 | 从原内容返回来源部门、权威单位、核验记录、有效期 |
| 正文相同就跳过导入 | 支持 source_id 定位的纯元数据或权限更新 |
| 推荐解释可能读取草稿、解释与评分脱节 | 复用第三阶段排序逻辑，只解释当前可推荐内容 |
| 前端没有校园 RAG 入口 | 侧栏新增“校园问答”，保留原有奖学金教务助手 |

## 权限与时效

推荐、内容详情、行为入口、RAG 检索与推荐解释共用 `content_visible`；角色、学院、专业、年级均参与判断，学院专业兼容代码与名称。

新增 `content_active`，统一排除未发布、未来发布、尚未生效或已失效资料。损坏的时效字段按不可用处理。推荐仍额外排除活动报名已截止的内容；RAG 可以检索历史活动资料，但政策有效期 `effective_to` 过期后不可作为当前答案来源。活动报名截止与资料有效期是两个不同字段。

`GET /rag/sources/{answer_id}` 重新检查：

1. 答案归当前用户所有，且未超过 24 小时。
2. 当前资料快照指纹与回答时一致。
3. 每条引用仍可访问，且仍在有效期内。

任何不满足返回 404，并提示重新提问。该校验阻止再次获取过期来源，无法撤回用户已经看到的文本。

## 索引和缓存

实现：`app/rag_index.py`。

- 内容变更：重建知识块并替换内存快照；同 ID 修改正文、权限修改、删除、下线均可被发现。
- 指纹覆盖实际数据库字段，不依赖导入脚本更新 updated_at，因此直接 SQL 改动也能在下一次请求被识别。
- 同一资料版本中，按当前可见内容 ID 集合缓存索引；不同权限资料集不混用 IDF 和矩阵。
- 最多保留 16 个范围缓存，LRU 淘汰；锁确保同一范围并发首次访问只训练一次。
- 有效期变化也会改变范围，即使没有数据库写入也不会继续检索过期内容。
- 初次查询或缓存失效后的首个查询训练索引，后续只转换问题。
- 每次仍读取已发布内容并计算指纹，成本为 O(资料总量)。本阶段消除了反复分块和训练，尚未实现数据库变更版本表或增量索引。
- 缓存为进程内缓存，重启后按需重建；多进程分别缓存。答案来源缓存同样不跨进程共享，当前适用于单进程毕设演示。
- 管理员/教师可 `POST /rag/rebuild` 强制重建知识块并清除本进程旧答案；范围 TF-IDF 在后续查询按需训练。

保留字符 TF-IDF、关键词与 RRF 融合，逐条筛除弱相关来源，每篇最多引用一个块，共最多 5 篇。无可靠结果固定拒答。完整关键词命中或字符相似度达到 `RAG_SEMANTIC_MIN_SCORE`（默认 0.30）才可入选；字符相似度不是语义理解模型或真实正确率。

当前 `/rag/ask` 使用本地原文摘录模板，不调用外部模型；DeepSeek 的现有教务助手链路保留。

## 来源字段与导入

新增到 contents：

| 字段 | 含义 |
| --- | --- |
| source_type | unknown / official_website / official_document / manual / other |
| source_authority | 资料维护者填写的权威发布单位 |
| last_verified_at | 人工核验时间，不能晚于当前时间 |
| effective_from | 生效时间 |
| effective_to | 失效时间 |

后端启动 `init_db` 会给旧表补充字段，不删除历史内容。SQLite 旧表迁移与重复执行已测试；MySQL 兼容 DDL 已保留，未在本轮连接真实 MySQL 验证。

不会根据“刚导入”或“有网址”自动标记已核验。旧资料仍显示未核验，source_type 标注为官网也不等于已经核验。前端只允许 HTTP/HTTPS 来源链接。

JSON 导入记录示例（示例时间仅说明格式，应按真实核验记录填写）：

```json
{
  "source_id": "existing-policy-id",
  "source_type": "official_document",
  "source_authority": "新疆工程学院教务处",
  "last_verified_at": "2026-09-20T09:00:00+08:00",
  "effective_from": "2026-09-01T00:00:00+08:00",
  "effective_to": "2027-08-31T23:59:59+08:00"
}
```

已有 source_id 可以只提供待修改字段；未提供字段保留原值，时间字段提供 null 可清空。日期时间建议显式提供 +08:00；无时区值按 UTC，纯日期 effective_to 按当天 UTC 日末处理。日期区间反转、未来核验时间或非法来源类型会拒绝该记录。

导入命令：`uv run python scripts/import_campus_data.py 路径.json`。每条记录使用独立保存点，坏记录不影响其他成功记录。SQLite → MySQL 迁移字段清单也已纳入来源元数据。

## 页面与接口

登录后侧栏“探索 → 校园问答”：输入问题后显示原文摘录、编号引用、发布单位、来源类型、资料更新时间、核验状态与有效期。“重新检查来源”调用来源接口重新校验；失效后清除当前答案，提示重新提问。

原“教务助手”继续进行奖学金评估，两个入口用途分开。

- `POST /rag/ask`：权限过滤、缓存检索、拒答或带来源摘录。
- `GET /rag/sources/{answer_id}`：当前权限下重新检查历史引用。
- `POST /rag/rebuild`：授权角色强制重建。
- `POST /rag/explain`：返回与第三阶段推荐一致的解释和 score_detail。
