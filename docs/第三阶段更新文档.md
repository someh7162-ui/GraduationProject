# 第三阶段更新文档

> 此文沿用早期 RAG 开发编号，对应总修改意见第四阶段的部分工作。总修改意见中的第三阶段（推荐算法优化）见 [第三阶段_推荐算法优化与验证](第三阶段_推荐算法优化与验证.md)。

> 本文保留早期实现记录。当前索引缓存、来源校验与前端入口以 [第四阶段说明](第四阶段_RAG权限缓存与来源验证.md) 为准；下方 Redis/embedding 为历史备选，不是当前阶段必做项。

## 阶段目标

本阶段围绕 RAG 校园问答与推荐解释完成实现，重点是：知识块切分、权限感知检索、混合排序、严格拒答、来源追溯和推荐解释。

## 已完成

- 新增 `knowledge_documents` 知识块表，保存来源内容、块序号、权限字段、发布时间、来源链接和模型标记。
- 对已发布 `contents` 按段落和长度切分，目标块长不超过 360 字，相邻块重叠约 50 字。
- `/rag/ask` 改为知识块检索，使用 TF-IDF 字符语义通道与关键词通道，并使用 RRF 思路融合排名。
- 统一复用 `content_visible`，学院、专业、角色和年级权限在 RAG 检索中继续生效。
- 对无可靠命中的问题返回固定拒答：`未找到可靠的校园资料，请尝试更具体的关键词，或联系辅导员。`。
- 增加 24 小时、最多 1000 条的进程内答案缓存，并提供 `GET /rag/sources/{answer_id}` 来源查询。答案来源按用户隔离。
- 增加 `POST /rag/rebuild`，管理员或教师可手动重建知识块索引。
- 增加 `POST /rag/explain`，根据兴趣标签、近期行为、截止时间和内容权限生成可解释推荐理由。
- 没有配置大模型时使用本地检索模板降级，不影响系统运行。

## 主要接口

| 接口 | 作用 |
| --- | --- |
| `POST /rag/ask` | 混合检索、拒答、模板式回答和答案缓存 |
| `GET /rag/sources/{answer_id}` | 查询答案引用来源 |
| `POST /rag/explain` | 生成推荐理由与原文来源 |
| `POST /rag/rebuild` | 管理员或教师重建知识块索引 |

## 技术实现

- 后端：FastAPI、SQLAlchemy、SQLite/MySQL。
- 检索：`scikit-learn` TF-IDF 字符 n-gram、关键词匹配、RRF 排名融合。
- 缓存：进程内 `OrderedDict`，TTL 24 小时，容量上限 1000。
- 权限：RAG 与推荐、内容详情共享 `content_visible`。
- 当前 embedding 字段已预留，默认记录 `tfidf-char-2-4`；后续可替换为外部 embedding 或 pgvector。

## 验证

- 后端第三阶段测试覆盖知识块、混合检索、拒答、来源查询、推荐解释和用户权限。
- 运行命令：`\.venv\Scripts\python.exe -m pytest -q -p no:cacheprovider`。
- 前端仍使用现有问答页面和 `/rag/ask` 兼容接口，不需要修改调用协议。
