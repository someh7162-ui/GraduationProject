# 第三阶段：推荐算法优化与验证

更新日期：2026-09-21。按 `Repaire1Demo/总修改意见/新疆工程学院_CampusAI_项目修改与优化建议.md` 第 14 节的阶段编号。

本阶段的代码、前端指标和离线评估工具已实现。合成样例仅验证评估流程；真实用户数据上的效果实验尚待开展，不能据此宣布真实推荐效果提升。

## 原因定位

1. 原实现把 view、click、favorite、share、register 合并到 positive 标签集合，无法区分行为强弱；dismiss 则统一扣 0.3。
2. 首页 92% 是固定字符串，与实际推荐无关；卡片把综合排序分乘 100 标为匹配百分比，也容易误解。
3. 没有可复现的 A/B/C 推荐对比和 Precision、Recall、Hit Rate、NDCG 计算工具。
4. 核心 API 测试仍用“计算机学院 / 软件工程”，注册时被新学院目录拒绝，导致登录、推荐与 RAG 测试连带失败。这不是算法运行报错。

## 评分规则

纯评分模块位于 `app/recommendation.py`，在线接口与离线评估共用同一实现。

| 行为 | 权重 |
| --- | ---: |
| view | 0.1 |
| click | 0.2 |
| favorite | 0.6 |
| share | 0.7 |
| register | 1.0 |
| dismiss | -0.8 |

- 同用户、同文章、同类型只采用最新一次行为；不同类型可以累加。重复点击不会堆叠分数，但最新互动会刷新衰减时间。
- 行为按 30 天半衰期衰减：`权重 × 0.5^(经过天数/30)`。
- 对每个标签累加，再用 tanh 压缩至 (-1, 1)，候选内容的行为分为其标签分的平均值。
- 仅使用当前用户、当前可访问且已发布内容的有效历史行为。未来时间、未知类型和无效时间的行为不参与计算；过期活动的历史仍可表达兴趣。
- 候选过滤统一检查角色、学院、专业、年级；学院专业支持名称与编码。未发布、未来发布和已经截止的内容不进入推荐。

```text
兴趣分 = 命中已选兴趣的标签数 / 已选兴趣数
身份分 = 学院、专业、年级三个维度中设置了匹配限制的维度数 / 3
内容分 = 0.85 × 兴趣分 + 0.15 × 身份分
新鲜度 = max(0, 1 - 发布时间距今天数 / 365)
紧迫度 = 截止剩余不超过1天为1，不超过3天为0.7，其余为0
最终分 = max(0, 0.55 × 内容分 + 0.20 × 行为分 + 0.15 × 新鲜度 + 0.10 × 紧迫度)
```

无发布日期不假定为最新，给予 0 新鲜度。无历史用户仍可使用兴趣、身份、时间获得排序。同分按内容 ID 稳定排序。所有权重都是明确的初始启发式参数，尚未由真实数据调参证明最优。

## 接口与页面

- `/recommendations?page_size=30`：限制 1–100 条，返回 items、total、metrics；未完成兴趣初始化仍返回 onboarding_required。
- `metrics` 包含 top_k、sample_size、matched_count、interest_match_rate。取本次返回列表前至多 10 条，按“至少命中一个用户主动选择的兴趣标签”计数；没有结果返回 null，页面显示“—”。行为标签不计为用户主动选择的兴趣。
- 首页显示“兴趣匹配率 · Top 10”及实际命中条数；这是当前列表指标，不是按自然日汇总，也不是离线 Precision@K。
- 卡片改为“推荐分”，提供兴趣、身份、反馈和截止时间解释。解释可悬停查看全文。
- 加入“不感兴趣”按钮；记录反馈后重新请求推荐与指标。
- `/events` 仅接受六种支持行为，并检查目标内容存在、已发布且用户可访问。

## 三方案离线评估

```powershell
.\.venv\Scripts\python.exe scripts/evaluate_recommendations.py data/recommendation_eval_sample.json --output docs/recommendation_eval_sample_results.json
```

| 方案 | 排序方式 |
| --- | --- |
| A / interest | 仅兴趣分 |
| B / identity | 兴趣 + 身份内容分 |
| C / hybrid | 内容分 + 行为 + 新鲜度 + 紧迫度 |

三方案均保留相同权限、发布和到期过滤；不能为基础方案关闭权限。对每个用户计算 K=5、10 的 Precision、Recall、Hit Rate、NDCG，再对用户取平均。Precision 的分母固定为 K，即使候选不足 K；NDCG 使用二元相关标签。

输入 JSON：

- `cutoff`：评估时点；`contents`：该时点的内容快照。
- `cases[].user`：该时点的用户身份和兴趣快照。
- `cases[].history`：严格早于 cutoff 的历史行为，包含 user_id、content_id、event_type、timestamp。
- `cases[].relevant_ids`：独立人工标注或 cutoff 之后留出的相关内容 ID，不能由本算法推荐分生成。
- 每个用户至少一个有效相关标签，且标签必须指向评估时点可访问、未到期、已发布的候选；输入不合格会报错。
- 真实实验应定义观察窗口、反馈标签规则与曝光范围，并保留时点快照，避免将未来兴趣、标签或权限信息泄漏到历史评估。

当前合成样例：3 个用户、12 条内容，用于跑通流程。NDCG@5 为 A=0.795618、B=0.871049、C=0.897809；Precision@5 三者均为 0.466667。这些数字不代表真实校园效果，不能作为论文的真实效果结论。
